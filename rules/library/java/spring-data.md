# Java Spring、事务与数据访问规范

适用于 Controller、Service、事务、MyBatis/JPA、数据库结构或接口契约改动。

## 分层与接口

- Controller 只做参数校验、协议转换和统一响应封装，不承载业务编排。
- Service 承载业务规则和事务边界；Repository、DAO 或 Mapper 只负责数据访问。
- 沿用项目已有响应类型和模块划分，禁止为单个需求新造重复的 `Result` 或 `Response` 包装。
- 参数较多时使用语义明确的 DTO，禁止用无约束的 `Map` 作为公共接口参数。

## 事务与远程调用

- `@Transactional` 仅用于 Service 的可代理入口；注意同类自调用不会经过代理。
- 事务中不得进行 RPC/HTTP 等远程调用；必要时通过事务后事件、消息或项目已有补偿机制处理。
- 捕获异常后若不能重新抛出，必须显式保证事务回滚语义。

## SQL 与 ORM

- SQL 明确列出字段，禁止 `SELECT *`；MyBatis 参数使用 `#{}`，禁止 `${}` 拼接。
- 金额和高精度数值使用 `decimal`/`BigDecimal`；判空使用正确的 SQL 语义。
- 修改数据前确认影响范围；更新记录遵循项目已有的审计字段约定。
- 数据库约束、索引和表结构必须以项目既有迁移工具与命名规则为准，禁止凭规则文件猜测生产库结构。
